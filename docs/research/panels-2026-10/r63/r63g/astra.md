**7. Deleted safeguards.** RS protected component access after startup. Its words, “let a component connect,” did not gate every operator or migrator session: neither old nor replacement text explicitly covers those non-components. S3-B′ does cover the engine’s startup-lock connection because it says “new store connection,” not “pooled connection”; this should be exercised. C7 protected capacity for reads and other writes; NA retains cancellation ownership and separate read capacity, but neither protects suspension-write availability under all-synchronous commits, nor bounds transport-loss/process-exit leftovers. Disabling self-restart made crashes detectable as full starts; B′ instead gates replacement sessions. Removing transaction pooling sacrifices a supported topology; removing forced backend reassignment loses that settings-test adversary, though CNF-56’s fresh-checkout assertion remains.

**8. Wrong builds.** (a) CNF-365’s withheld-position assertion catches a write-only check **if replication remains healthy**; the fixture should say so and explicitly assert no writes/waiters. (b) CNF-365’s “refuse every new connection” catches unchecked fallback when the withheld read reaches its timeout. (c) No guaranteed topology check: a pooler that disconnects frontends on backend failure can pass the crash drill despite the blanket ban. (d) CNF-296’s cancellation/overload assertion, provided the test first fills the write budget. (e) None guaranteed: CNF-365 does not require unequal durable histories followed by standby restarts; both incorrect reports can tie in a passing fixture. (f) PT’s CNF-365 assertion, “promotes neither as a restart.” PA-2 also needs an automatic-restore refusal assertion.

**9. Strongest counter-case.** Certify only actual outward commitments; a real logged write in the deposit-read transaction, acknowledged before the response, closes H-a and the cross-history barrier error without pool hooks, statistics grants or restart settings. H-d2 supports it. But `04:1291` says “A read MUST NOT take a write transaction,” requiring an explicit API-54 amendment. Another read path remains: enqueue X stalls, crash recovery exposes it, an idempotent retry reads and returns X, promotion loses X, and a changed-payload retry under that key creates Y. `API-11`, `04:936–938`, says “Re-sending it with a different request MUST fail `409 Conflict`” and “MUST NOT create a second operation.” Deposit-only certification is therefore insufficient for the existing retry contract.
