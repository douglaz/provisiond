(c) — retain observation-based caching; explicitly accept failed-read consumption of the tenant budget.

The gap is real. The endpoint promises “Re-read from the provider” ([04-api-contract.md:13](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/04-api-contract.md#L13)); `API-7` says “enqueue an operation, then `202`” (line 247). `OPS-8` allows “At most one `running` operation” ([03-operation-lifecycle.md:183](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/03-operation-lifecycle.md#L183)), not a cooldown after settlement. `OPS-11` says refresh failures are “Always `failed`” (line 223). A read establishing nothing cannot advance the timestamp defined as “when `state` was last established by an authoritative read” ([05-persistence.md:276](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/05-persistence.md#L276)); `DOM-8` explicitly takes staleness from that timestamp ([01-domain-model.md:136](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/01-domain-model.md#L136)). Another operation can therefore read immediately. The reserve protects system provider capacity; the additional machine bound chiefly prices tenant-budget interference. That does not justify another persistent clock by itself.

- **The failure cases differ.** `PRV-5` maps transport, timeout and non-2xx failures, including `authentication`, `not_found` and `rate_limited` ([02-provider-contract.md:32](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/02-provider-contract.md#L32)). Thus 5xx, timeout, 429 and a non-authoritative post-create 404 can leave observations stale. But “404 inside the window” is insufficient: `PRV-36` says “A read showing the post-mutation state is evidence at any time” (line 866); absence after deletion differs from absence after creation. `PRV-41` already makes authentication failure “terminal for that credential” on lockout-prone providers (line 945). That is a credential-level prohibition, without a specified refresh-attempt timestamp.

- **Recorded errors are not enforced cooldowns.** `operations.error` exists ([05-persistence.md:370](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/05-persistence.md#L370)); `WIR-9a` supplies `retry_after_ms` for `rate_limited` ([13-wire-contract.md:131](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/13-wire-contract.md#L131)). Neither defines admission of the next refresh. ADR-0035 adds no remedy: `PRV-5` explicitly assigns acceptance `false` to “a read-only operation with no mutation” ([02-provider-contract.md:40](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/02-provider-contract.md#L40)).

- **Deliberately forcing upstream failure is not established.** `WIR-23` accepts only “body `{}`” ([13-wire-contract.md:739](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/13-wire-contract.md#L739)); callers select owned internal machine identifiers, not arbitrary provider requests. They can target a post-create visibility race or exploit an existing outage; the spec supplies no general way to force persistent 5xx, authentication failure or timeout. During failures, one machine can nevertheless consume tenant capacity. The operator incurs request processing, worker/store load and tenant denial, without a new purchase. The reserve does not reserve workers: `OPS-24` fairness remains “SHOULD” ([03-operation-lifecycle.md:1575](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/03-operation-lifecycle.md#L1575)).

- **(a) needs additional semantics, even if no additional column.** The listed operation timestamps are not dispatch timestamps; `available_at` is “earliest claim time” ([05-persistence.md:372](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/05-persistence.md#L372), line 383). An operations query needs a defined clock, qualifying rows and retention. Counting enqueue times permits delayed operations to dispatch together. If an unconditional dispatch bound is wanted, a nullable `machines.refresh_attempted_at`, committed before dispatch while holding the machine, is simpler. Stamping only settled failures misses crashes; stamping suppressed refreshes lets callers perpetually extend suppression.

- **(a) also changes the freshness promise.** After repeated failures, cached state can be arbitrarily old. Moreover, “returning cached state with its true timestamp” is not today’s wire contract: `WIR-10b` gives refresh result `{}` ([13-wire-contract.md:277](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/13-wire-contract.md#L277)), and `WIR-11` omits `state_observed_at` entirely (line 295). ADR-0034’s assertion that callers already read it is false.

- **The bound cannot cover every provider read.** `DOM-8` includes reads “opportunistically after actions”; `OPS-32` requires independent account reconciliation ([03-operation-lifecycle.md:1321](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/03-operation-lifecycle.md#L1321)). A refresh cooldown must not suppress either. Their authoritative observations may satisfy the cache predicate.

- **(b) is honest but adds recovery delay and the same clock.** Use existing `rate_limited`/retry-after if selected; no new error taxonomy is needed. **(c)’s cost must be explicit:** withdraw ADR-0034’s unconditional bound and “many paid machines” attack-price claim. Strongest don’t-build: correct that overclaim; do not manufacture stale-cache success or durable cooldown machinery to preserve it.

No new column. No failure-classifier declaration changes: preserve `Provisiond.Tables.classify` and `refresh_always_failed` ([Tables.lean:180](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/tools/formal/Provisiond/Tables.lean#L180)). The settled budget/reserve work remains separately owed.
