**Verdict: (c) — count successful observations for the refresh cache and explicitly accept the failed-read residual.**

The gap is real in ADR-0034’s literal “at most one provider read” claim. A provider 5xx, `429`, authentication failure, timeout, or a `404` that cannot establish absence leaves `machines.state_observed_at` stale; a reported refresh failure settles `failed`. Once that operation settles, `OPS-8` permits another to run. With the **decided but not yet specified** request budget and reserve in place, that loop can consume tenant capacity and deny other tenants work, but it cannot spend the stated system reserve through refresh admission. The strongest reason to avoid a failure cooldown is that this repository shows no reliable way for a tenant to choose those provider failures. A cooldown would add durable state and delay a useful retry after an outage clears. An authentication lockout is a real operator risk, but `PRV-41` identifies it as a credential-wide problem; a per-machine timer is the wrong control.

**Defects in the framing**

- “Already in the operations table” is false. `created_at` records enqueue, `updated_at` is not dispatch time, and `claim_number` identifies a claim rather than an attempt. `OPS-45` excludes refresh from its marker rule. A precise attempt bound needs a durable pre-dispatch fact, such as `machines.last_refresh_dispatched_at`, or a new indexed operation marker retained for at least the window. Querying settlement `updated_at` gives a conservative *settlement* cooldown only if actual provider attempts can be distinguished from local refusals; otherwise each refusal can extend the cooldown. ([05-persistence.md:382](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/05-persistence.md#L382), [03-operation-lifecycle.md:1207](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/03-operation-lifecycle.md#L1207), [05-persistence.md:1359](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/05-persistence.md#L1359))
- “Return the cached state with its true `state_observed_at`” assumes a field the machine view does not expose. `updated_at` cannot substitute for it. Returning a *successful refresh* after the preceding read failed would also imply evidence the provider never supplied. Option (b) is more honest, but still needs the attempt fact and a specified local error and pacing rule. ([13-wire-contract.md:295](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/13-wire-contract.md#L295), [05-persistence.md:276](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/05-persistence.md#L276), [03-operation-lifecycle.md:223](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/03-operation-lifecycle.md#L223))
- A `404` inside `PRV-36`’s visibility window is not authoritative evidence *about a recent mutation*; `PRV-36` does not make every refresh `404` the same failure. A later authoritative absence may update the cache. ([02-provider-contract.md:824](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/02-provider-contract.md#L824), [02-provider-contract.md:864](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/02-provider-contract.md#L864))
- The “per-machine provider read” wording also sweeps in reads during other operations and `OPS-32`’s account sweep. Those may refresh `state_observed_at` independently; a bound on **refresh operations** is not a bound on all provider reads. `OPS-8` only serializes operations while running. `ADR-0035` expressly leaves refresh’s failure row unchanged because it has no accepted mutation. ([01-domain-model.md:125](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/01-domain-model.md#L125), [03-operation-lifecycle.md:183](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/03-operation-lifecycle.md#L183), [03-operation-lifecycle.md:1321](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/03-operation-lifecycle.md#L1321), [03-operation-lifecycle.md:261](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/03-operation-lifecycle.md#L261))
- The reserve is an accepted **decision**, not yet a landed requirement: `OVR-19` and `PRV-40` still specify only an order budget. The ADR itself lists the outstanding edits. Until those land, the old operator-cost exposure remains. ([ADR-0034:36](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/docs/adr/0034-tenant-traffic-cannot-spend-the-providers-request-budget-the-system-needs.md#L36), [ADR-0034:68](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/docs/adr/0034-tenant-traffic-cannot-spend-the-providers-request-budget-the-system-needs.md#L68), [00-overview.md:380](https://github.com/douglaz/provisiond/blob/0c52755a3ee60dd2e71937a58dff45c9f2e0cc91/00-overview.md#L380))
