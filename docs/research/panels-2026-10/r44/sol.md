**Verdict: Choose (1).** Defer retention of a settled create while its attached machine still reads `provisioning`; keep vanished-row sweep deletion for rows removed under that rule.

A successful create needs an exact correlator match and a direct machine read, but that read does not establish that key injection or first boot has finished ([03-operation-lifecycle.md:494](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/03-operation-lifecycle.md#L494)). Robot accepts a fingerprint with the order; the live test deleted the key only after `ready` and showed that the *transaction still listed the fingerprint*, not that earlier deletion was safe ([Robot API](https://robot.hetzner.com/doc/webservice/en.html), [live result:5](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/docs/research/panels-2026-10/r39/live-result.txt#L5)). Cloud’s create action and DigitalOcean’s first boot leave consumption timing unverified ([provider research:115](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/docs/research/provider-verify-2026-10.md#L115), [provider research:443](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/docs/research/provider-verify-2026-10.md#L443)); DigitalOcean’s assurance about deleting an account key applies to existing Droplets, not this in-flight interval ([DigitalOcean documentation](https://docs.digitalocean.com/platform/teams/how-to/upload-ssh-keys/)). `STO-14` specifies a configured age, with no minimum or bound on how long `provisioning` can remain observed ([05-persistence.md:1408](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/05-persistence.md#L1408)).

**Defects**

- [ADR-0040:35](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/docs/adr/0040-a-lost-auction-order-is-resolved-by-its-fingerprint-and-a-temporary-key-outlives-an-unsettled-operation.md#L35) and [PRV-9:128](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/02-provider-contract.md#L128) each pair a “no machine … still reads `provisioning`” condition with unconditional deletion when the operation row vanishes. Their claim that no machine can be attached after row loss overlooks one attached *before* retention.
- [STO-14:1408](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/05-persistence.md#L1408) and [OPS-25:1621](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/03-operation-lifecycle.md#L1621) require aged settled rows to leave without that exception; [OPS-32:1459](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/03-operation-lifecycle.md#L1459) repeats unconditional vanished-row deletion.
- [CNF-303:2439](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/10-conformance-checklist.md#L2439) tests provisioning and vanished rows separately. [Rescue.lean:911](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/tools/formal/Provisiond/Rescue.lean#L911) assumes absent row means absent attachment, while [keyEligible:972](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/tools/formal/Provisiond/Rescue.lean#L972) deletes in the disputed combined state; [the witness:3030](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/tools/formal/Provisiond/Witnesses.lean#L3030) never tests retention crossing it.

**Edits:** Give `STO-14` a narrow create exception until the machine leaves `provisioning`; align `OPS-25`, `PRV-9`, `OPS-32`, and ADR-0040. Test retention at the configured age while provisioning persists, then observation, sweep deletion, and retention. Model guarded retention in Lean and prove the vanished-plus-provisioning state unreachable through that transition.

**Don’t build:** Do not add a durable key-to-machine registry or discard the guard on a “days versus minutes” assumption. The machine’s single correlator value does not identify every possible registered key ([05-persistence.md:266](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/05-persistence.md#L266), [PRV-9:140](https://github.com/douglaz/provisiond/blob/1f70010edb55987ede8424c13231f954ee7736e6/02-provider-contract.md#L140)). Both required unpiped gates passed; tracked files remain clean.
