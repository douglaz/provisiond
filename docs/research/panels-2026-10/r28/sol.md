**Amend** — put known offer unsellability after account health, then the applicable ordering channel’s closed budget, before solvency, rate, cap, and balance. Keep priced checks when a healthy account’s known offer has a price.

The order is observable: [API-7](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/04-api-contract.md#L261) makes entry 0 determine HTTP status, `kind`, message, and pacing. I recommend `409 conflict` with a new machine-readable reason `offer_not_sellable` for the offer; `429 rate_limited` with `retry_after_ms` for the closed channel. An agent seeing the offer headline should select another offer rather than wait for the throttle. The offer might become sellable after the live test in [ADR-0039](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/docs/adr/0039-only-offers-with-no-traffic-overage-are-sold-until-a-counter-is-proven-fresh.md#L33), so “permanent” describes the useful action now, not an eternal property. A budget headline tells the agent when that channel can be tried again. A subordinate refusal retains its own details, but does not lend its pacing to the headline.

| Create case | Ordered refusals and headline | Priced checks |
|---|---|---|
| Unhealthy account + **known** unsellable offer | Account `conflict/state`, then offer `conflict/offer_not_sellable`; HTTP 409 | Skip for `provider_account_not_healthy` |
| Unsellable offer + its closed channel | Offer, then `rate_limited`; HTTP 409, no headline throttle delay | Run if rate exists |
| Healthy, sellable offer + closed channel + short balance | `rate_limited`, then `insufficient_balance`; HTTP 429 with channel delay; envelope `retryable: false` | Run |
| Unsellable offer + no rate | Offer, then `halted/rate_unavailable`; HTTP 409 | Skip for `rate_unavailable` |
| Standard offer; only auction channel closed | No order-budget refusal | Run normally |

**Defects in the framing**

- Filtering does not make a remembered offer `not_found`: [ADR-0039](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/docs/adr/0039-only-offers-with-no-traffic-overage-are-sold-until-a-counter-is-proven-fresh.md#L68) separately requires listing filtration *and* a purchase-tail refusal. The current [WIR-30](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/13-wire-contract.md#L962) has not yet acquired that filter. A truly nonexistent offer is a distinct case; [DOM-17](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/01-domain-model.md#L560) reserves `not_found` for a resource that does not exist.
- Unsellability does not establish that pricing is unavailable. [DOM-9](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/01-domain-model.md#L181) requires an offer’s prices; [API-7](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/04-api-contract.md#L268) skips priced checks for no rate or an unhealthy account. Adding a third skip would hide a computable cap or balance refusal and require changing [WIR-9a](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/13-wire-contract.md#L141)’s closed reason set. The smaller shape adds no skip reason.
- `conflict/state` alone would give account and offer failures the same machine-readable reason. [WIR-9a](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/13-wire-contract.md#L136)’s closed reason set needs a distinct offer reason; agents should not parse `message`.
- The budget belongs to the account **and ordering channel**, not every offer on the account: [ADR-0036](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/docs/adr/0036-the-robot-order-budget-is-closed-by-the-providers-throttle-and-not-shared-out.md#L34). Calling it the request’s own resource is imprecise. Its position can still follow the named offer because [ADR-0030](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/docs/adr/0030-purchase-tails-report-all-applicable-refusals.md#L8) prioritizes the named resource before broader faults.
- “Admission-only” in [OPS-11](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/03-operation-lifecycle.md#L234) classifies a failure before a driver call; it does not place it before the tail. [ADR-0036](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/docs/adr/0036-the-robot-order-budget-is-closed-by-the-providers-throttle-and-not-shared-out.md#L70) explicitly calls for an API-7 tail edit. By comparison, [SEC-39’s ceiling](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/04-api-contract.md#L223) is expressly step 5c; [API-41’s shedding](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/04-api-contract.md#L881) is enrolment-specific. Neither relocates this create refusal.
- [API-50](https://github.com/douglaz/provisiond/blob/023ed3fc743bd1d4926c92d9d571f943e65dc86e/04-api-contract.md#L1202)’s rate-pacing promise needs a scoped clarification: another tenant can trigger this shared provider throttle before this caller has received a hint. Subsequent `429`s must carry `Retry-After`; following that hint cannot guarantee the channel will remain open.
