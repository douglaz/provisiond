**Verdict:** Use the server’s successful recording time for an operator-sourced `observed_at`. Store it as `operator_recorded_at`; remove `observed_at` from the record request.

The agent uses `restricted` to stop a destructive remediation loop: [DOM-27](https://github.com/douglaz/provisiond/blob/7d21478c29e2a82d6540bd7a84b5a8dc5351dc7b/01-domain-model.md#L348) calls that “The signal’s job.” The operator needs to know how long a positive record has remained without withdrawal. [ADR-0038](https://github.com/douglaz/provisiond/blob/7d21478c29e2a82d6540bd7a84b5a8dc5351dc7b/docs/adr/0038-a-network-restriction-is-positive-evidence-from-either-source.md#L62) says the rendered time “shows the record’s age” because a stale positive can invite deletion of a working machine. The time on a lock notice dates the notice; it does not establish when the block began or when the operator last recorded it.

**Defects in the proposed framing**

- An optional supplied time would give one field two meanings: notice time when supplied, recording time when omitted. Refusing future times would catch some errors but not backdating, a typo, or clock skew. A date before this database’s machine row is not necessarily wrong: [OPS-32](https://github.com/douglaz/provisiond/blob/7d21478c29e2a82d6540bd7a84b5a8dc5351dc7b/03-operation-lifecycle.md#L1392) describes a late-attached machine that existed at the provider first. The current supplied field is at [WIR-47](https://github.com/douglaz/provisiond/blob/7d21478c29e2a82d6540bd7a84b5a8dc5351dc7b/13-wire-contract.md#L1211).
- `SEC-32` does **not** establish that recording time is already available: its required audit fields end with “target machine, and outcome”; they include neither a timestamp nor the request body or `operator_ref` ([07-security-requirements.md:288](https://github.com/douglaz/provisiond/blob/7d21478c29e2a82d6540bd7a84b5a8dc5351dc7b/07-security-requirements.md#L288)).
- The provider side dates **our read**, as [ADR-0038](https://github.com/douglaz/provisiond/blob/7d21478c29e2a82d6540bd7a84b5a8dc5351dc7b/docs/adr/0038-a-network-restriction-is-positive-evidence-from-either-source.md#L33) says “when it was read.” The two clocks need no ordering rule. Where both sources are positive, the settled provider preference can render an older provider read and hide a newer operator record; the displayed time is the selected source’s age, not the newest evidence ([ADR-0038:36](https://github.com/douglaz/provisiond/blob/7d21478c29e2a82d6540bd7a84b5a8dc5351dc7b/docs/adr/0038-a-network-restriction-is-positive-evidence-from-either-source.md#L36)).
- A same-key replay returns the stored body under [WIR-24](https://github.com/douglaz/provisiond/blob/7d21478c29e2a82d6540bd7a84b5a8dc5351dc7b/13-wire-contract.md#L771); changing a supplied instant under that key would be an idempotency mismatch under [WIR-3](https://github.com/douglaz/provisiond/blob/7d21478c29e2a82d6540bd7a84b5a8dc5351dc7b/13-wire-contract.md#L36). A correction or renewed record needs a new key. Also, `operator_ref` is absent from the specified machine-view object ([WIR-47](https://github.com/douglaz/provisiond/blob/7d21478c29e2a82d6540bd7a84b5a8dc5351dc7b/13-wire-contract.md#L1222)); the view alone cannot supply the follow-up reference.
