## Supersession trace

`STO-56:1377` says "at most one row may have `closed_at` null". `STO-56:1394–1402` says "The operator MUST NOT close the record until" step (3) is marked, `grace_ends_at` has passed, the account sweep's second pass is done, every waiting parent is confirmed or cancelled, and each currency has either a full rate-present interval since step (3) or every machine gone or fenced. "Closing at the original end alone MUST NOT disable unspent paused grace for a currency with a live unfenced machine."

C5 excepts one transaction from that lead. On an actual restore whose store contains open R, that transaction closes R, retains R, and inserts a distinct open row with `supersedes_incident_id = R`, `steps_completed = 0`, `grace_ends_at = null`, `closed_at = null`. No component starts across that boundary. `STO-54:1557–1559` already requires the establishing transaction to be acknowledged before either component starts. A process crash creates and supersedes nothing.

1. **Restore-classified promotion.** `STO-54:1550–1553` says any promotion that is not the full-WAL restart "is a restore" and "`STO-56`'s record is committed into the promoted store before either component is started." That is the establishing transaction, so provenance initialization and supersession run if that store has an open incident. A restart-classified promotion (`STO-54:1539–1545`) establishes no new record. An open incident there is continued. The column is not re-initialized. "Actual store restore" is not a backup-only term under that reading.

2. **Process successor.** No new incident. Y-PROV-R preserves the bit. Y-WIDE-R sets it in the same guarded transaction as an open-incident move to `needs_reconciliation`. A lost reply rolls status and bit together. A committed repeat affects no row (`STO-3`). Closure and purge clear neither package's true bit.

3. **Second supersession.** A backup that holds closed R and open B yields C, which closes B and names B. B's marks do not satisfy C. Provenance is applied again to surviving unsettled install and rescue-inventory rows. Settled rows with false stay false.

4. **Lost establishment reply.** One chosen id and instant. An absent id is the initial establishment. The same id, instant, and predecessor is a guarded no-op that keeps that row's step marks and original instant, not R's marks. A mismatch, including reuse of R's id, is refused and both components stay stopped. That is C6's lost-reply case: not two open incidents, and not a silent continuation on predecessor marks.

5. **What the close guard was protecting.** The exception does not drop the system into an ordinary restart. The new open row is the only row `OPS-41` and the startup read use.

Adverse funding trace. A has finished step (3), wall-clock `grace_ends_at` has passed, currency C has accumulated less than one re-derivation interval, and a live machine in C is unfenced. Close is forbidden. The backup holds that state. Supersession closes A and opens B with grace null.

`OPS-41:987–992`: "while a restore record is open and its `grace_ends_at` is null or in the future the claim MUST defer" by the ordinary short delay when the instant is not yet written, and it writes no fence. B's null grace takes that branch. No component can observe A's close without B's insert. They are one transaction, and components are stopped. The paused check is not reached in the gap. `Fence.pausedGrace` (`Fence.lean:546–550`) is false when `graceEndsAt` is none, and true only for the record it is given. After B's step (3), `STO-56:1385–1387` writes B's own `grace_ends_at` once, as that step's instant plus one interval. `OPS-41:1006–1015` accumulates rate-present time "From step (3)'s instant, derived as `grace_ends_at` minus one re-derivation interval" of the open record. A's partial accumulation is not credit and is not a remainder. C must satisfy a new full window. Unspent paused grace is not disabled. It is replaced by a longer fresh obligation. Machines are not cancelled early.

The same replacement re-runs the new procedure. `STO-54:1606–1613`: a second credential bump "can invalidate and never resurrect", and a second derivation-index skip "allocates forward". Both are the safe direction the repeat rule already states, now on purpose because "no predecessor step mark satisfies a new step". Customers who re-issued under A re-issue again. That is what a new lost interval requires (`STO-54:1591–1593`), not a breach of "a customer that re-issued after step (3) keeps the token", which is about not repeating the same incident's marked step. `CNF-295:1022–1028` still says the process successor of one incident does not rewrite `grace_ends_at` and does not kill the re-issued token. C5 does not make that assertion vacuous. A mere crash still creates no incident.

Waiting parents: B's `steps_completed = 0` runs step (2) again. `OPS-15:406–409` waits on a `suspend_tenant` parent found `running`, or `queued` and unsettled. A's confirmation does not satisfy B's close condition. The sweep: `STO-54:1620–1624` says the first pass after a restore records nothing about absence because observations in Δ are gone, and a second pass separated by the effective window may. That is the new incident's procedure, not A's pass count. A's finished second pass does not authorize absence on B and does not meet B's close condition.

I do not add a collateral amendment. The open-row rule (`STO-56:1378–1379`) and "full procedure and close conditions" already pick these verdicts. `closed_at`'s exact timestamp on R is unspecified. Any non-null value frees the partial index, and no grace read uses it.

Setting the Boolean is not why this is acceptable. The record can be established, the predecessor cannot stay open beside it, and the obligations the close guard names are re-imposed on the new incident rather than dropped.

## Preference and costs

Y-PROV-R. A process crash after fresh admission does not restore an earlier database. `CONTEXT.md` Restore: "a restart loses no acknowledged commit". `OPS-45:1570–1571`: each marker write is "acknowledged by the store before the provider call it precedes is made." Y-PROV-R renders those commits. Y-WIDE-R hides them after closure and purge even where, in its own words, no restore rolled those markers back, including a committed clean exit and a null column that `OPS-45:1494` says is the only value meaning no session was opened. W stays ACCEPT because `unknown` is not the lie `CNF-302` names, a crashed session rendered `none`.

Both add admission metadata, a retained column, a staged backfill, a pre-start bulk update of every surviving unsettled install and rescue-inventory row, and supersession metadata. WAL and recovery delay are unmeasured. The unsettled backlog is not assumed small. Legacy settled errors can lose ordinary wire facts. The already-reconciling row can change none/unknown to unknown/unknown with no status transition. Y-WIDE-R also writes the bit on each specified open-incident transition and hides that operation's marker facts after closure and purge. Y-PROV-R preserves that distinction and is harder to get right. Supersession grants a new full grace and a new rate-present window and discards the predecessor's partial accumulation as credit. None of this is negligible or owner-approved.

Neither package turns `needs_reconciliation` into `failed`, replays the operation, proves bytes landed, or infers a session from status.
