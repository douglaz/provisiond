**1. Claims.** All six hold at `cdc6adf`. Two sharpenings:

- C1 proves option 2 wrong, not 1′ right. `conflict` is "State or idempotency conflict" (01:580); a record predating its reader is neither. No `DOM-17` row fits. `conflict` is the least-wrong kind a worker may emit that is neither ambiguous nor a defect, and `price_moved` already uses it for "the accepted record is stale against the present" (03:723-724).
- C6's gap is pre-existing: `price_moved` states no `retryable` anywhere (13:137; 10:2548-2551). State both in the same edit, or 1′ becomes the only claim-time refusal with one.

**2. Pick: 1′.** Strongest argument is C2: `retryable` is "normative guidance to callers" (01:654), and the same request succeeds at any N `api`. `false` orders an obedient agent to abandon a purchase the system would accept.

**3. Mid-roll.** Honest. `WIR-9a`'s own `true` rows describe conditions that persist: `halted` "can succeed when the gate clears" (13:161), `conflict`/`state` "can recover" (13:163). `true` means the same request succeeds once the condition clears, not now. A repeat into an N−1 replica fails identically and buys nothing (12:1264); the roll ends. Other kinds: install settles `failed` "for any failure at all while `OPS-45`'s two markers say the disk is untouched" (03:231). Power, delete, reverse-DNS and release use the last row, and a pre-provider `conflict` is not ambiguous (03:265). `API-51`'s second-destructive-write warning applies only "while the first's outcome is unresolved" (04:1250-1251); this one is resolved. Release is create-only: "an install or a delete opens none" (12:322). Option 3 needs an `OPS-11` exception on five rows, not one: `internal` is ambiguous everywhere (03:263-264; `tools/formal/Provisiond/Tables.lean:136`).
