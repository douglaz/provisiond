**Verdict:** Robot’s limits warrant targeted controls for refresh and reset, but the published reference does not establish a shared counter across server numbers, webservice users, or source IPs. Do not build a generic request budget.

| v1 path | Robot traffic and who can drive it |
|---|---|
| Refresh | A stale refresh can call `GET /server/{n}`; a tenant can repeat it. Fresh observations settle from cache. |
| Create and resolution | Offer reads, temporary `/key` calls, an order POST, transaction reads or polls, then a direct `GET /server/{n}` to confirm the delivered machine. Resolution and the sweep need those reads as evidence. |
| Delete | `GET /server/{n}/cancellation` supplies `reserve_location` eligibility before the cancellation POST. Tenant deletes and system cancellations reach it; a successful delete also triggers attachment listing. |
| Sweep and attachment release | `GET /server` enumerates the account; missing machines require direct `GET /server/{n}` before recording absence. Additional IPs and subnets require `/ip` or `/subnet` reads and, where they survive, cancellation calls. |
| Rescue, inventory, install, power | Rescue uses `/boot/{n}/rescue` reads and mutations, host-key polling, and `POST /reset/{n}` to enter and exit. A tenant can initiate rescue, inventory, install, or hard reset; an accepted rescue needs its exit reset. |
| Reverse DNS | PTR reads or writes use `/rdns/{ip}`; tenant writes already have a principal ceiling. |

These routes and limits appear in [Robot’s webservice reference](https://robot.hetzner.com/doc/webservice/en.html). Its `403 RATE_LIMIT_EXCEEDED` response includes an interval, but the reference does **not** identify the counter’s user, account, IP, or server-number scope. Four machines refreshing once per 60 seconds produce 240 detail reads per hour **if** their requests share the documented 200/hour counter; that exhaustion is conditional, not verified. Orders limit *new* machines to documented daily requests, but an existing paid server can generate repeated resets. The 50/hour reset limit matters most when a rescue entry succeeds and its exit then meets a throttle.
