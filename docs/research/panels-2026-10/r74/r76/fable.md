## Q1 — pv-c7vg, P4C

| Package | Verdict |

| P4C, one printed form | ACCEPT, conditional on its declared trust contract; every addition behaviour changed, as declared |

Preference: P4C. Strongest argument: a mutation boundary prevents what polling cannot retract, and request-start expiry bounds new use without a per-commit round trip or a healthy-wait false alarm.

1. **Boundary.** P4C prevents only changes the sole authority mediates and says so: "Administrative bypass remains outside prevention"; "Nothing here asserts prevention of a bypass commit between observation and refusal". It relies neither on command-line pinning nor on another session's SHOW ("An observer's SHOW/pg_settings reads do not prove another session's GUCs"); session settings rest on "trusted component SQL". The pinned settings docs confirm the limits: ALTER ROLE/DATABASE values "override values obtained from the configuration files or server command line", and SET "has no effect on other sessions", so role defaults for `synchronous_commit` fall inside the authority's declared scope and a pin alone would not cover them.
2. **Bounds.** Drift at t0; a round starts within C and ends or fails within Q, so the latch is set by t0+C+Q. The last "safe" reply any component can hold was requested before the latch and expires V after its request start, so new use stops by t0+C+Q+V with nothing heard; delayed receipt cannot extend it. The text claims only new use: "A transaction admitted before permission expires can still send COMMIT after expiry"; "No new external dispatch, deposit exposure or api success is permitted after refusal"; no durable-report bound. api "exits within A", which is how in-flight requests receive no success, so no new payload is needed beyond the existing `overloaded` for pre-transaction refusal. STO-7's retained sent COMMIT is quoted and kept.
3. **Residuals.** P3's latch is not imported: "A known residual backend alone is not evidence of unsafe replication configuration or topology; this observer does not establish a residual-capacity bound", and CNF-296's addition keeps the one-standby success reachable after the contending engine's exit. A residual backend has no client, so it issues no new commit; its unverifiable setting matters only to a pending COMMIT the drift itself releases, which configuration observation covers. No Q3 ledger is required; no unobservable session is certified. Ambiguity, not defect: "Idle sessions MUST be rechecked each round" can only mean pooled component sessions, since a residual has no checker.
4. **Reads and records.** CNF-296's "a read still succeeds" (10:1071) survives by the printed fixture restriction (declared behavioural). CNF-299 and every other write fixture presuppose a conforming deployment, which under P4C runs the observer; no literal text flips. CNF-362 anchors are unique ("with a working store." 10:1663; the "unless the case says otherwise" sentence 10:1720–1724). A denied record attempt is an OPS-49 store error with no SQL, a refused try; `finished_unrecorded_exit` (StopRecord.lean:432) already exits on `plan.tries.length = storeBudget` or the Stop-record bound, so "posture refusal is not an additional immediate exit" holds and no disjunct is added. The engine "stops under OPS-21", every record is gated, the bounds end it, rows stay `running`, OPS-15 classifies at restart: exactly the appended control.
5. **Collateral and cost.** Observer sessions join STO-55's human budget row (declared). A latch or observer failure stops api within A and needs "operator reset": one full outage per latch. Maintenance during a stall needs drainage or primary shutdown, STO-7's only exception. I found no MUST/SHOULD loss to name.

Conditions: exclusive authority over configuration, reloads, role/database defaults, deployed SQL, routing and credentials; trusted component SQL; monotonic local clocks and a watchdog; observer capacity budgeted. ## Q2 — pv-3jw6, UO versus F

**Formal home (verified).** `RestoreTrace.store` writes `restoreInstant := t.now` with `delta` separate (Restore.lean:163–168); `afterCrash` reloads it into `now` (:435–438); `bootRestore` uses `t.now` (:541); `step_three_writes_grace` uses the completion event's `instant` (:548). Both candidates keep every assignment and define `restore_instant` as `transaction_timestamp()` of the incident-insert transaction, an event. A documentation clarification is sufficient synchronization: no declaration changes meaning, and neither claims the Nat model proves timestamp semantics. Grace stays step (3)'s own instant in both.

**Inclusion proof.** Let R be the last replayed commit or abort record, s its timestamp, e a bound on the source clock's error at that read. R's timestamp is taken before insertion (xact.c:1446; abort analogous), so R is inserted at true time ≥ s−e. A commit C acknowledged at true time t < s−e was inserted before t, hence before R, hence at a lower LSN; a continuous recovered prefix on matching ancestry containing R completely therefore contains C. No timestamp-to-insertion delay bound is needed: a longer delay on R moves R later, which strengthens the claim; C's delay is irrelevant because its acknowledgement follows its insertion. So b=s−e certifies every earlier acknowledgement without asserting timestamp order equals WAL order. The only countertrace is against an exact end: A samples 10 and pauses, B samples 11 and inserts, A inserts; the prefix through A holds B, so opus's "A commit generated after that time is absent" is false, and neither candidate prints it. Endpoint: insertion strictly precedes acknowledgement, so an acknowledgement at exactly b is covered too; F's (b,f] is defensible and UO's [b,f] is the more conservative; a precision choice, not a defect. Note for both: "acknowledged before b" is a true-time statement; an operator comparing against logs on a third clock must add that clock's error.

**Evidence (challenge 3).** Both require the replay read before any restart (the pinned docs: NULL "When the server has been started normally without recovery") or the identified record in retained WAL; both require matching ancestry and no hole; both reject a bare LSN, filename or START TIME; neither needs the old primary; both make capture and retention an operational obligation (OVR-19 human rows). f=restore_instant+e rests on ADR-0047's ordering, which both quote. Both persist endpoints once and reuse them across interruption and changed allowances.

**Restore arms (challenge 4).** CNF-358's "restore that backup with an open restore record and start the engine" (10:1540–1543) is a restore arm; both list CNF-99/295/297/302/358/370 and the seeds CNF-29/99/218/271/308 without claiming exhaustiveness. CNF-295's "the operator report names `T − Δ`" (10:1044) is replaced by both (declared). 05:1561 is unique; the 05:1656 sentence exists across a line wrap (1656–1657).

**Allocation (challenge 5).** 05:924 "Allocated strictly increasing and never re-issued" and CNF-297 "exceeds every index a rolled-back row held" stand. With restored maximum m, gap g and more than g+1 lost allocations, the next index can repeat one; a known duration gives no count. Omitting U4's gate changes no existing obligation; it declines a new enforcement mechanism. Neither candidate waives no-reissue or adds allocation wording.

| Package | Verdict |
|---|---|
| UO | ACCEPT; whole schema (two nullable endpoints, non-null evidence reference), certificate and unknown policy accepted as printed, all behaviour changed as declared |
| F (U2R) | AMEND, behaviour changed (below) |

**F's defect.** It makes "U2's new CNF-365 restore drill" a success fixture requiring valid bounds without printing it. That drill's arm "repeat with that store restarted and its switch segment removed before capture: no record, no component start" contradicts F's own fallback "or recover the identified record from retained WAL": removing one segment does not remove a record retained or archived elsewhere, so F's rule can produce a record where the drill asserts none. F also adds `loss_end_at`, which the drill never asserts.

**F AMEND.** Location: `q2-F-sol.md`, the sentence beginning "Successful actual-restore fixtures in the checklist". Before: "and U2's new CNF-365 restore drill". Replacement: "and this CNF-365 addition: 'Promote, as an operator's restore, the standby with the unavailable report; assert `lost_window_starts_at` is its last replayed transaction's time less the allowance and `loss_end_at` is the record's `restore_instant` plus the allowance; repeat with that store restarted, its switch segment removed before capture and no retained or archived WAL holding that record: no record, no component start.'" Behaviour changed: a fixture restriction and a new assertion. This is not acceptance of a repaired F.

Preference among acceptable printed forms: UO. Strongest argument: the certificate is sound, the event clock stays the event clock, and no outage is spent on a report nothing automated consumes (bump, quarantine and skip are window-independent at the pin). Mechanics: UO is sound as printed; F is sound once its fixture is printed, and with that one repair both would be technically acceptable. The tradeoff is the owner's: F keeps components stopped until finite endpoints are proved and yields an auditable interval at the price of a potentially indefinite outage; UO never adds an outage for a report and may publish "unknown". Costs: UO two nullable columns, one reference, capture and retention, clock discipline; F two non-null columns, the same discipline, the hold.

## Q3 — pv-oehp, B3R versus B4*

**Invariant (both).** Actual backends ≤ unreleased grants ≤ C, injective because every physical dial carries its own grant before dialing, unknown attempts stay charged, nothing releases on timeout, death, lease expiry or leaving `SyncRep`, and release waits for fenced delayed capabilities plus fresh termination evidence. Pre-authentication occupancy is charged by construction, which role limits cannot do: a PGPROC exists before `PerformAuthentication` (postinit.c:704, :900) and before the role count (miscinit.c:873–880), and the reserve check runs after the slot is claimed (postinit.c:929–951). PID reuse: boot identity plus `backend_start`. Driver fallbacks: the pinned libpq docs say "each host will be tried in turn" and `sslmode=prefer` means "first try an SSL connection; if that fails, try a non-SSL connection", so one connect call can be several dials; both forbid redial under one grant (B3R "prohibit bypass and redial", B4* "redial under one reservation"), which an implementation meets only by disabling fallbacks: a condition, not a gap. Fresh observation: B4* says "read in a fresh transaction"; B3R says "fresh authoritative evidence", which a transaction-cached activity snapshot would not satisfy. Lock holders, migrators, waiting runners, observers and operators are in C or A in both; internal server pools are budgeted separately; both fail closed on accounting loss with conservative reconstruction or stopped-components primary shutdown.

**C1 (mine)** is not defended. The guard survives in both drills: B3R "Failed replacement checks remain closed unused"; B4* "attempts fail unused". Residue is reached honestly: B4* by waiting PIDs plus withheld check replies with retained server legs; B3R also by "pause commits before local flush", reachable only with external instrumentation inside the interrupt-held segment (xact.c:2358 HOLD_INTERRUPTS precedes :2381 RecordTransactionCommit and :1506 XLogFlush). The deferred `pg_sleep` trigger fires at :2278 and checks interrupts (misc.c:396), so it is not that instrumentation; B3R names no mechanism, so its step is a fixture obligation, not a false claim.

**Reads and collateral (challenge 4).** Both restrict CNF-296/299 to retained admitted read sessions and promise no reads after all are lost. STO-55's consumer sentence (05:213) is replaced by both; B4*'s is the brief-resolved astra text. OPS-47 (03:137) and CNF-290 (10:1517) are amended by both; the healthy arm "release the first and assert the second then starts" survives with admission available, and an exhausted arm is added, explicitly indefinite in B3R's OPS-47 and as "delays replacements" in B4*. CNF-362: a record uses the worker's held connection, so admission touches it only on a redial; B4* restricts it explicitly, B3R leaves the literal fixture reachable. Stop-record and Store-retry bounds are consumed, no new exit, no SyncRep cancellation in either; OPS-21's supervisor wait stands.

**Routing (challenge 5).** B4* prints startup exit for supervisor retry, api `overloaded` before any transaction, worker/periodic OPS-49 store error, and stop-record refusal. B3R prints OPS-49 and OPS-47 and relies on STO-55's existing "obtains no connection within a stated checkout bound (`OVR-19`) is refused `overloaded`" for api, which holds because a refused dial yields no connection.

| Package | Verdict |
|---|---|
| B3R | ACCEPT, conditional, all behaviour changed as declared |
| B4* | ACCEPT, conditional, with the consumer sentence resolved to astra's exact text |

Preference: B4*. Strongest argument: grant-before-dial charges the pre-authentication slot every server-side count misses, and refusing release on death is what stops double-spending a slot a vanished process still holds. B4* is preferred for its printed error routing, fresh-transaction observation and a drill that needs no pre-flush pause.

**Opus's dissent, carried.** B2's strength is that the server counts every authenticated backend of a role with no external state to lose; its cost is accepting a time-bounded pre-authentication class. That class cannot meet the question's invariant: `authentication_timeout` bounds "client authentication", not PGPROC lifetime, and a reconnecting burst occupies slots outside every role count and ahead of the reserve check. B2 bounds authenticated backends, not physical occupancy; choosing it is choosing the weaker invariant.

Costs: a durable serialized issuer as a new availability dependency, idle reserves, indefinite restart delay at exhaustion, primary shutdown when accounting cannot be reconstructed, observer resources.
